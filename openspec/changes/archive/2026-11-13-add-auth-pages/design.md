# Design

## Context

See proposal.md for motivation. Current state that shapes the approach:

- **Data layer.** Prisma 8 (`@prisma/orm-postgres` 8.0.0-rc.22) with `src/prisma/contract.prisma` as the single source of truth. Table names follow model names (`Deck`). Columns follow field names. The app connects to Neon's direct endpoint through `directConnectionUrl()` (`src/prisma/connection-url.ts`), because Neon's pooler rejects Prisma's session settings.
- **Better Auth.** Better Auth 1.7 lists `@prisma/client` up to version 7 as its Prisma peer, so its Prisma adapter targets the classic client, not Prisma 8. Its built-in Kysely adapter accepts a `pg` `Pool` directly. `pg@8.22.0` is already in `node_modules` as a Prisma dependency.
- **Better Auth 1.7.14 core schema** (read from `@better-auth/core/dist/db/get-tables.mjs`). All ids are string ids generated by Better Auth.
  - `user`: `id`, `name`, `email` (unique), `emailVerified` (boolean, default false), `image?`, `createdAt`, `updatedAt`.
  - `session`: `id`, `expiresAt`, `token` (unique), `createdAt`, `updatedAt`, `ipAddress?`, `userAgent?`, `userId` → user (cascade, indexed).
  - `account`: `id`, `accountId`, `providerId`, `userId` → user (cascade, indexed), `accessToken?`, `refreshToken?`, `idToken?`, `accessTokenExpiresAt?`, `refreshTokenExpiresAt?`, `scope?`, `password?`, `createdAt`, `updatedAt`.
  - `verification`: `id`, `identifier` (indexed), `value`, `expiresAt`, `createdAt`, `updatedAt`.
  - `rateLimit` (only with `rateLimit.storage: "database"`): `id`, `key` (unique), `count`, `lastRequest` (bigint).
- **Rendering.** `cacheComponents: true`. `/` and `/icon.svg` are static, and `/decks/[id]` is a partial prerender. The header lives in the root layout, so reading `headers()` there would make every page dynamic. The `marketing-home` spec also forbids database queries while rendering `/`.
- **Security headers.** The static CSP allows same-origin `fetch` (`default-src 'self'`), which covers the browser auth client calling `/api/auth/*`.
- **Fonts.** `app/layout.tsx` loads Geist, Geist Mono and Outfit. `globals.css` maps `--font-sans` to Geist, `--font-heading` to Outfit and `--font-mono` to Geist Mono.
- **Open change.** `redesign-brand-and-theme` is not archived. Its 2 remaining tasks are the browser review and a `vp run build` blocked by a Windows file lock on `src/prisma/contract.d.ts`. This change edits the same header and the same font requirement.

## Goals / Non-Goals

**Goals:**

- Working email and password accounts, with Better Auth's built-in protections (hashing, origin and CSRF checks, rate limiting) in force.
- One schema source of truth, including the auth tables.
- Auth pages that faithfully reproduce the provided design in both themes.
- No loss of static rendering for the existing pages.

**Non-Goals:**

- Ownership, protected routes, "My decks", password reset, email verification, social sign-in, account settings and avatars. These are the next change.
- A custom adapter for Prisma 8.

## Decisions

### D1. Better Auth's built-in adapter over a `pg` Pool, with tables owned by the Prisma contract

`src/auth/server.ts` (`server-only`):

```
betterAuth({
  appName: "AI Pitch Deck",
  database: new Pool({ connectionString: directConnectionUrl(), max: 5 }),
  emailAndPassword: { enabled: true, minPasswordLength: 8, maxPasswordLength: 128, autoSignIn: true },
  session: { expiresIn: 7 days, updateAge: 1 day, cookieCache: { enabled: true, maxAge: 5 min } },
  rateLimit: { storage: "database", customRules: { "/sign-in/email": { window: 60, max: 5 },
                                                   "/sign-up/email": { window: 60, max: 5 } } },
  databaseHooks: { user: { create: { before: validate + trim name with Zod, else APIError 400 } } },
  plugins: [nextCookies()],   // last, per the docs
})
```

- **Secret and URL:** `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL` are read from the environment by Better Auth. They are never put in config literals.
- **Tables:** the five tables are declared in `contract.prisma` with `@@map("user")` and so on, and field names identical to Better Auth's, such as `emailVerified` and `expiresAt`. Ids are `String @id` with no generator, because Better Auth writes them. `lastRequest` is `BigInt`.
- **Applying them:** `vp exec prisma db update` applies the tables to the development database. That command is additive and never resets.
- **Schema check:** Better Auth's startup check stays on, so a mismatch between the contract and Better Auth's expectations fails loudly in development.
- **Pools:** Better Auth's pool is separate from Prisma's, which is acceptable at this scale. `max: 5` keeps the two well inside Neon's connection limit.

_Alternatives:_

- **Better Auth's Prisma adapter:** it needs Prisma 7's client.
- **A custom Better Auth adapter over `db.orm`:** more code and more risk, with no benefit for five standard tables.
- **Better Auth's `migrate` command:** it would create tables outside the contract and break the data-access spec.

### D2. Auth forms post through the Better Auth browser client, not Server Actions

`src/auth/client.ts` exports `authClient = createAuthClient()` from `better-auth/react`, with no `baseURL` because the app is same-origin. The forms call `authClient.signUp.email({ name, email, password })` and `authClient.signIn.email({ email, password })`. Requests then go through `/api/auth/*`, where Better Auth applies its rate limiter and its origin and CSRF checks. Calls made through `auth.api.*` inside a Server Action bypass the request router.

- **In the browser:** the forms validate with the shared Zod schemas from `src/auth/validation.ts` (`SignUpSchema`, `SignInSchema`) to give immediate field messages.
- **On the server,** validation is enforced by:
  - Better Auth's own email checks;
  - the password length options;
  - the `user.create.before` hook, which runs the same Zod name rule (trim, 1 to 100 characters).

**Trade-off:** sign-in and sign-up need JavaScript. This is accepted, and the pages are useless without the client anyway.

### D3. Error mapping

Better Auth returns `{ error: { status, code, message } }`. `src/auth/errors.ts` maps codes to user-facing text and never shows the raw message:

| Better Auth code                           | Message                                                          |
| ------------------------------------------ | ---------------------------------------------------------------- |
| `INVALID_EMAIL_OR_PASSWORD`                | "Invalid email or password."                                     |
| `USER_ALREADY_EXISTS*`                     | "An account with this email already exists." plus a sign-in link |
| `PASSWORD_TOO_SHORT` / `PASSWORD_TOO_LONG` | The password field rule                                          |
| `INVALID_EMAIL`                            | The email field rule                                             |
| status 429                                 | "Too many attempts. Please wait a minute and try again."         |
| anything else                              | "Something went wrong. Please try again."                        |

Unknown codes are logged in the browser console without the password, then mapped to the generic message.

Sign-up does reveal whether an email is registered. This is accepted for usability, and the per-client rate limit mitigates it. Sign-in never reveals it.

### D4. Header account state read in the browser

`components/site/account-menu.tsx` (`"use client"`) uses `authClient.useSession()`:

- **Pending:** a fixed-size placeholder (`size-8`), so nothing shifts.
- **Signed out:** a `ghost` "Sign in" link.
- **Signed in:** a round button with the person's initials, `aria-label="Account menu for <name>"`. It opens a `dropdown-menu` with the name, the email and "Sign out". "Sign out" calls `authClient.signOut()`, then `router.refresh()`.

`MobileNav` gets the same session hook and appends "Sign in" or "Sign out".

Server rendering of every page stays session-free, so `/` remains static and the `marketing-home` "no database query" rule still holds. The session fetch is a separate same-origin `GET /api/auth/get-session`, served from the signed cookie cache for 5 minutes at a time.

_Alternative:_ read the session in the layout inside `<Suspense>`. Rejected because it turns `/` into a partial prerender and queries the database on every home page request.

### D5. Pages and the shared auth layout

```
app/(auth)/layout.tsx       grid-frame shell: full-height <main> with a centred column
                            (max-w-md) bounded by vertical border lines, and horizontal border
                            lines above and below the card row; "+" marks at the 4 crossings
app/(auth)/sign-up/page.tsx metadata "Create your account"; title, subtitle, <SignUpForm/>,
                            "Already have an account? Sign in"
app/(auth)/sign-in/page.tsx metadata "Sign in"; "Welcome back", subtitle, <SignInForm/>,
                            "Don't have an account? Create one"
app/(auth)/_components/
  auth-card.tsx             bg-card rounded-2xl ring-1 ring-foreground/10 p-8 (the white card)
  icon-input.tsx            label (sr-only) + Input with a leading Pikaicon, h-12, rounded-xl
  password-input.tsx        IconInput + trailing eye toggle (aria-label Show/Hide password)
  sign-up-form.tsx          "use client": name / email / password, Zod, authClient.signUp.email
  sign-in-form.tsx          "use client": email / password, Zod, authClient.signIn.email
```

- **Faithful to the screenshot:** a bold centred title (`text-3xl font-semibold`), a muted two-line subtitle, the card with comfortable padding, 48 px rounded inputs with a muted leading icon and placeholder text that matches the screenshot, and an outlined full-width submit (`variant="outline"`, `h-12`). Below the card sits the switch line, with a muted sentence and a bold link.
- **The grid lines** are `border-border` (or `bg-border`) spans, and the "+" marks are two crossed 1 px spans in CSS. Nothing is hand-drawn as SVG, and there are no gradients.
- **Placeholders don't replace labels:** each input has a visually hidden `<label>` and the placeholder is the visible hint, as in the screenshot. Errors render under the field, tied to it with `aria-describedby`, in the shadcn `FieldError` style.
- **After success:** `router.push("/")` and `router.refresh()`.
- **Inputs:** `components/ui/input` comes from shadcn (`vp dlx shadcn@latest add input`) and is restyled through `className`.
- **New icons,** searched and added with the Pikaicons CLI as free icons: user, mail or envelope, lock, eye, eye-off and logout.

### D6. `proxy.ts`: optimistic redirect for signed-in visitors

```
export function proxy(request) {
  return getSessionCookie(request) ? NextResponse.redirect(new URL("/", request.url)) : NextResponse.next();
}
export const config = { matcher: ["/sign-in", "/sign-up"] };
```

`getSessionCookie` (from `better-auth/cookies`) only checks that the cookie exists, which is acceptable for a redirect away from a form. It is never used to grant access. The redirect target is the fixed relative path `/`.

### D7. Inter everywhere

- **Fonts in `app/layout.tsx`:** load `Inter({ variable: "--font-inter", subsets: ["latin"] })`, and remove Geist, Geist Mono and Outfit.
- **`globals.css`:**
  - `--font-sans: var(--font-inter)`;
  - `--font-heading: var(--font-inter)`;
  - `--font-mono: ui-monospace, SFMono-Regular, Menlo, Consolas, monospace` (system font, no download).
- **Headings:** they keep their weight classes (`font-semibold`) and use `tracking-tight` for Inter's display sizes.
- **Wordmark:** the logo wordmark is live text, so it follows automatically.

## Risks / Trade-offs

- **[Two connection pools]** Prisma's and Better Auth's pools both connect to Neon. → `max: 5` on the auth pool. On serverless each instance has its own pool, which matches the existing Prisma setup.
- **[Schema drift between Better Auth and the contract]** → Better Auth's startup schema check stays on. The version is pinned exactly (`1.7.14`), and an upgrade must re-read `get-tables` and update the contract.
- **[Sign-up reveals registered emails]** → Accepted for usability, mitigated by rate limits. Sign-in uses one message for all failures.
- **[Rate limiting off in development]** Better Auth enables it in production by default. → The spec scenario is production-scoped. The limit can be exercised locally by setting `rateLimit.enabled: true` temporarily.
- **[No password reset]** A forgotten password cannot be recovered yet, because there is no email provider. → Documented. It comes with an email provider in a later change.
- **[Client-only header state]** The header shows a placeholder for a moment on first load. → The placeholder is fixed-size, and the cookie cache keeps the session request fast.
- **[Open prerequisite change]** → Task 1.1 stops until `redesign-brand-and-theme` is archived.

## Migration Plan

1. Archive `redesign-brand-and-theme`.
2. Install the dependencies. Add `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL` to `.env`, and document both in `.env.example`.
3. Add the auth models, run `vp run contract:emit`, then `vp exec prisma db update` on the development database. It is additive. For a production database, plan a migration with `prisma migration plan` instead.
4. **Rollback:** revert the commit. The auth tables can stay in the database harmlessly, or be dropped deliberately by a person. Never reset the database.
